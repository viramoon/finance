# 期权流观察与历史核验

F9e 为已确认的 SMART USD 美股期权提供进程内接口。观察结果是共享 OPRA L1 的待核验线索。历史结果是指定合约和时窗内，从 IBKR 历史回调取得的逐笔证据与方向估计。两类结果分别计算计数，分别保留 UTC 接收时间、成交发生时间和核验时间。

## 实时观察

- 调用 `LiveOptionFlow::watch(line_handle, ObservationEngine::default(), policy, usage)` 订阅已有 [行情线调度器](integrations/ib-line-budget.md)。启动调度器前建立观察者可接收首批行情类型回调。调用方在调度器停止时取消等待。观察者与页面共用现有行数。
- 只处理实际 `marketDataType=1`、非延迟的合约回调。轮换、断线、行情类型改变、会话段改变或消费滞后时重置对应采样状态。消费滞后后需要新的实际行情类型证据。交易时段使用经确认合约的 `liquid_hours`。每条线索附调度预算快照，F9b 可查询时另附已覆盖、未覆盖和未知的时窗。样本时钟相同形成零宽窗口，或窗口末端晚于调度时钟时，覆盖为 `None`。覆盖依据 F9b 的合格行情回调，描述本地观测范围。
- `ObservationEngine::summary(as_of)` 返回观察数、放量线索数、超基线数、价差扩大数、读者滞后数和最近线索接收时间。默认规则 `ibkr_l1_observation_v2` 按同标的 conId、同到期日及交易段开始后每 30 分钟分组。分组滚动保留近七天的最近 32 个样本，至少 3 个才有中位数基线。奇数样本取排序后的中间值，偶数样本取中间两个值的算术平均。速率基线用精确的张数分子与毫秒分母表示。
- 同一连续窗口内两次累计量的正差记为放量线索。30 秒以上的差分、计数回退和失去覆盖后的首个样本重建基线。按窗口毫秒数比较历史速率，达到中位数的两倍标为放量超基线。中位数为零时，有可计算速率的正差也标为超基线。基线样本不足或窗口不足一毫秒时，`elevated` 为空。保留独立带时标的 last/size 样本。有合格采样价时可估算 `采样价 × 量差 × 实际合约乘数`，该金额对应整个差分区间的估计。两个相邻累计量快照之间可能包含多笔或漏采，单笔规模留待历史证据。
- 报价线索比较有效双边价差与分组中位数，规则要求五秒内的价量和至少两倍的价差。价差中位数超出精确十进制可表示范围时，该次比较不产生线索。每条线索的状态是 `pending_verification`，页面可显示“观察到放量/报价异动，待核验”。

## 历史逐笔核验

1. 接入方沿用 `ConnectionManager` 开立经 paper 守卫验证的只读 `PaperMarket`，在该会话确认期权 conId，使用 `PaperMarket::option_history(data_root)` 取得历史源。若与行情调度器同时运行，由接入方分配独占的已审核 client ID。复用 F11 历史 pacing 状态，单次请求超时 45 秒，请求之间至少间隔 16 秒。核验同批候选可用 `prioritize_history(contracts, market_date)` 将当日可查的 0DTE 和最近到期日排在前面。
2. 用 `HistoricalWindow::new(start, end, quote_start, max_pages_per_kind)` 给出同一美东交易日期的常规交易时段 `[start, end)`。三项时间均为 UTC 整秒。查询可给报价留同日的前置窗口。每个种类最多 64 页，单次请求 1,000 条，供应商可返齐末秒而超过 1,000。
3. `OptionHistoryIngress::verify` 接受经确认的合约、F1 标的、核验策略及可选的 F9b 覆盖。标的须为 USD 期权，实际合约乘数一致，并带 `ibkr/opra-history` 对应的十进制 conId。归档保留 `TRADES` 和 `BID_ASK` 各自的请求起点、页号、请求 ID、接收时间、源秒和秒内出现序号。
4. 分页接受带完成回调的批次，下一页从已完整处理的末秒后一秒开始。收到覆盖已处理秒的重复行时比较各行的多重集合，相同价和数量的两笔保留两个出现位置，重叠不一致标为待核验。无权限、限流、超时、未完整和达到页数上限保留具体未完成区间。已过期的合约在请求前标记不可回补。无历史与不支持由来源返回明确原因。历史窗内缺失的逐笔由历史证据说明，分钟 bar 和 L2 各有自己的覆盖。

## 历史证据和标签

- `HistoricalEvidence` 保留核验时间、实际乘数、成交发生与取得时钟、原始条件码、映射版本、状态、配对报价和报价年龄。计数独立给出已核验活跃成交、其中方向未知、待核验原始成交行、不可回补区间、待处理区间、未匹配更正和非成交标记。TRADES 页之间存在完整秒记录冲突时，冲突报告覆盖的原始行标为 `pending_verification`，进入 `pending_trade_rows`，保留批次并停用方向、规模及权利金推断。区间按 TRADES、BID_ASK 各自计数。
- `verify_history` 检查早于成交的最近一个源秒的报价是否符合策略指定的最大年龄。偏向 ask 或 bid 时返回推测主动买或推测主动卖，并附规则与置信度。中间价、陈旧、锁盘、交叉、无有效报价、报价缺口、同秒先后不明及复杂腿分别保留未知原因。权利金用精确十进制按 `成交价 × 张数 × 实际乘数` 计算。缺失或精度越界时保留空值。IBKR Protobuf 价格从其 binary64 字段按最短往返十进制转换一次。数量直接解析源的十进制文本。
- 默认 `ibkr-opaque-v1` 原样留存条件码，空码与未识别的非空码区分。调用方有经过核实的供应商映射时，可按版本映射明确的复杂腿、扫单、块单、更正及取消。显式回放关联可提供原记录 ID、目标 ID 和修订序列。IBKR 公共历史回调缺执行关联 ID，接入路径保留无法配对的更正或取消证据。条件码和规模推断分别呈现，代码未聚合缺少关联信息的记录为扫单。
- 规模阈值可启用“疑似块单”或“疑似机构规模”标签，报告给出触发阈值。成交参与者身份始终为 `unknown`。

## 许可、存储与集成

`ibkr/opra` 用于内存观察。`ibkr/opra-history` 独立审核，`FlowUse::PrivateDisplay` 需要 `display_live`，`FlowUse::NonDisplayDerivation` 需要 `derive_non_display`。历史源和 F3 入口使用同一个工作树外的 `FERTILE_DATA_ROOT`。开启 `record_local` 时，F3 `MarketIngress` 从已解析的数据根逐级打开 `finance-state/market-wal/ibkr/opra-history`，拒绝符号链接及嵌套的 Git 工作树，并通过持有的产品目录句柄读写原始记录和元数据。可展示历史数据也可在 F3 的短时内存缓存读取。历史请求仍在已有 `finance-state/historical` 维护限速状态，该目录仅写入限速元数据。告警、外发和个人盘备份各按已有授权边界处理。

历史原始数据分别以 `option-history-trades`、`option-history-quotes` 流发布，按 F3 写者代次重置。本地结果确认时返回持久水位。每次重新查询取得独立的批次证据，页内重叠去重范围限本次查询。若记录失败，按 F3 恢复查看已确认前缀后重试。选择性传入 F9b 覆盖时，仅在已知常规交易时段且 TRADES 请求完成的未观察区间记录 `tick_backfilled`。计数是该区间收到的原始交易流记录数，包括保留的供应商标记。查询和覆盖采用半开区间，转换为 F3 质量报告时将结束时间减一纳秒，使报告的含端点区间指向相同范围。条件码和报价均进入投影供追溯。

历史证据使用 [v3 事件契约](../protocol/v3/event.schema.json)，观察报告、方向与规模推断通过 Rust 进程内接口取得。已有 [F3 读取 API](api.md#首批读契约) 可读取获准发布的历史证据。后续读契约接入按 `finance → web → frontend → fertile` 同步，并在调用历史核验前校验私有授权。F9d 的 GEX 与 F9e 相互独立。运行时继续使用现有行情会话与数据根，无专用服务或监听端口。
