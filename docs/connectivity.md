# 连接、恢复与风险职责

本设计沿用 [fertile ADR-001](https://github.com/viramoon/fertile/blob/main/docs/adr/ADR-001-cloud-box-network-constraints.md)。下表描述依赖能力和 finance 需要补的配置、验证与业务规则，不能把上游已有能力等同于本项目已验证可用。

| 规则 | Nautilus / ibapi 已有职责 | finance 的职责与验证 |
| --- | --- | --- |
| 心跳、读超时、退避重连 | 使用 Nautilus IB adapter 及其 ibapi 连接能力 | 在 config 中映射心跳、超时、退避上限与抖动；锁定版本后核对参数；模拟静默断线、连续失败与恢复 |
| 重连后重订阅 | Nautilus IB adapter 提供重订阅基础 | 明确订阅清单、权限与恢复完成条件，验证重复订阅、漏订阅和标的映射 |
| 按断点补历史数据 | 使用上游历史数据请求能力 | collector 管理断点、补数范围、去重和缺口核验；自动补齐策略不能假设上游已覆盖全部数据 |
| 账户 / 订单 / 成交对账 | Nautilus 执行引擎已有启动 / 执行对账能力 | 配置启用对账、恢复范围、超时；启动先获取快照与本地状态核对，不一致时保持暂停；验证断线期间成交和进程重启 |
| 下单幂等 | 使用 Nautilus 客户端订单标识与 IB 映射 | 每单唯一客户端 ID / orderRef，跨恢复保留映射；写超时先查订单与成交，再决定是否重试，禁止无条件重试 |
| live / ready | 不将连接对象存在等同于业务健康 | 每进程 /healthz 区分 live 与 ready；ready 需认证、订阅、数据新鲜及对账可信，格式和端口 TBD |
| 行情陈旧熔断 | 使用上游风险规则 / Actor 扩展点 | finance 拥有阈值与状态机：超阈值或订单状态不可靠时暂停开新仓，只允许撤单和查询；撤单仍须先查后试；对账通过并满足恢复条件才继续 |
| profile 与路径 | 上游配置作为依赖输入 | 只在配置层区分 cloudbox / stable，运行模式独立，所有运行时路径位于配置指定的 /home/box 默认根目录下 |

## 启用与验证设计

选定 Nautilus 版本后，把 [配置字段](../config/README.md) 映射到上游真实配置类，记录对账开关、启动超时、客户端 ID 和恢复策略。TBD：精确参数名、阈值、持久化缓存后端与自动恢复条件，由后续连接验证 issue 确认，不编造 API 名称。

启动顺序设计：载入持久状态 → 连接与认证 → 恢复订阅与数据水位 → 拉取账户 / 持仓 / 订单 / 成交快照 → 对账 → 满足 ready 后允许策略开仓。失败不绕过对账；自动恢复只在状态可信时进行。

验收应覆盖静默断线、断网、认证失效、限流、订单响应丢失、Gateway 重启和云电脑重启，记录断线时间、恢复耗时、错误类型、源 IP（可见时）与行情延迟。按 ADR 用真实业务协议在 paper 环境连续观察 24～72 小时；本次仅写设计，尚未进行这些运行验证。

finance 不依赖 Cloudflare Tunnel；web / frontend 故障不应中断交易。读请求可按策略重试，写请求先查后试；不通过换 IP 绕过平台限制。现网异常按 [RUNBOOK](../RUNBOOK.md) 处置并关联 fertile tag。
